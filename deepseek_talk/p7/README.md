# P7 数据包（Ours-5，与 ChordEdit 严格同为 5 次 UNet 前向）

给 Claude 的纯数据 + 报告（约 0.35 MB）。

## 三句话（**负面结果，必须照实传达**）

1. **同等 5 次前向、匹配背景 PSNR 下，Ours-5 输给 ChordEdit 2.44 nat（胜率 22%）**，比 P6 的
   −0.91 更差。
2. **原因不是效率也不是背景保真，而是语义强度**：所有 Ours-5 变体的 CLIP-Edited 都卡在
   19.9–20.4，ChordEdit 是 **22.59**。
3. **机制已定位**：ChordEdit 的编辑场是 `0.143·R(0.9) + 0.857·R(0.75)`，我们的是 100% `R(0.9)`
   —— 而 P3a 测过 `R(0.9)` 有 97% 是噪声。方向从一开始就弱。

## 我们设计的三件事，各自的结果

| 改动 | 设计目的 | 实测 |
|---|---|---|
| 双尺度融合（等能量权重） | 用上已算好的低噪场 | 无效（0.00）→ 应改弦权重 |
| 核心收紧 + **能量归一** | 防 k 项把步长撑爆 | 归一有效；γ=2→3 无改善 |
| **Masked-Prox**（+1 NFE） | 前景清理 + 背景保住 | **固定 λ 下 +4.4 dB 背景；等 PSNR 后反而 −0.63 nat** |

## 一个必须一起看的结论

**掩码局部合成把"背景保真"变成了可以无限透支的额度**：为了把背景降到和 ChordEdit 一样的
22 dB，掩码内部被推到 λ=2.55（全图 prox 只要 0.74），于是语义反而更差。所以
"固定 λ 下 26.7 dB vs 22.0 dB"这个工程上的胜利，**不能**写成"在同等保真下更好"。
