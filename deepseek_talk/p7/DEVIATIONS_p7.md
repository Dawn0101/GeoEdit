# P7（Ours-5，与 ChordEdit 同为 5 次前向）

## P7-D1. 背景 PSNR 作为唯一匹配轴是可被利用的（本轮最重要的方法学教训）

- 预注册（`configs/p7.yaml`）沿用 P6 的"匹配**背景** PSNR"。
- 问题：掩码局部合成 `x_out = (1−M²)x_s + M²·prox` 让背景**几乎无条件**接近源图，于是"背景 PSNR"
  变成一个可以无限透支的额度 —— 为了把背景降到和 ChordEdit 一样的 22 dB，掩码内部被推到 λ=2.55
  （全图 prox 只要 0.74）。结果是：**固定 λ 下掩码 prox 明显最好（+4.4 dB），等背景 PSNR 后反而
  最差（−0.63 nat vs 全图 prox）**。
- 处理：本轮**照预注册报告**（主判定仍是匹配背景 PSNR），同时把三种轴（背景 PSNR / 全图 DINO /
  CLIP-Edited）都列出来（§3.1），并在 §5.2 明确写"P8 应改用全图 DINO 或双轴约束"。
  这不是改判定，是记录判定的局限。

## P7-D2. 双尺度融合用的不是弦权重（所以没效果）

- 我按"等能量"融合：`u = u_h + w·(‖u_h‖/‖u_l‖)·u_l`，实测与不用低噪场**完全一样**
  （o5 − o5_nofuse = 0.00 [−0.00,+0.06]）。
- 事后读 ChordEdit 的 `_u_estimate` 才发现它的权重是弦权重
  `u = (δ·R(t_s) + t_s·R(t_s−δ))/(t_s+δ) = 0.143·R(0.9) + 0.857·R(0.75)` —— **86% 来自 t=0.75**。
  我们的缓存没有 0.75，且等能量权重与弦权重完全不同。这条写进 §2/§3.2，作为 P8 的首选改法。
