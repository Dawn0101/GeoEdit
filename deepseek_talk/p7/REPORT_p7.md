## 1. 三个短板的修法（代码在 `geoedit/edits.py`，全部有单测）

### 1.1 双尺度场融合（0 额外 NFE）

P6 只用 `R(t_h=0.9)` 做内容，把已经算出来的 `R(t_l=0.5)` 只用于做掩码。现在把它也用上：

```
u = u_h + w · (‖u_h‖ / ‖u_l‖) · u_l          # 先按范数对齐，再融合 → 融合是"方向"而不是"幅度"
u ← γ_dir · u,  γ_dir = max(0, cos(u_h, u_l))  # PreciseEdit eq.9，每图一个标量
```

按范数对齐这一步是必须的：`‖R(0.5)‖` 的中位数只有 `‖R(0.9)‖` 的 0.15 倍，直接相加等于没融合。

### 1.2 核心收紧 + 幅度重标定（0 额外 NFE）

```
δ_raw = λ · M ⊙ (u + k · M^γ ⊙ A_h),   γ ∈ {2, 3}
δ     = δ_raw · (λ‖R_h‖ / ‖δ_raw‖)              # 能量归一
```

- `M^γ` 只作用在 **A 的推项**上：A 的 `‖e_src‖ = 1.77‖R‖`（P6 §1），不收紧就会把 `e_src` 摊到
  掩码尾巴上，P6 里 λ=1 的 PSNR 从 30 掉到 19.18 就是这个原因。
- 归一后 `‖δ‖` 对所有 `(k, γ, gate)` 都一样，等于把 λ 网格变成纯粹的"幅度旋钮"，于是**匹配
  PSNR 的比较只差方向与空间分布** —— 这正是我们想测的东西。

### 1.3 Masked-Prox：第 5 次前向（+1 NFE = 5）

```
y      = x_s + δ
prox   = x0_pred(a_c·y + b_c·ε, t_c = 0.3, c_tar)      # 1 次 UNet，与 ChordEdit 的 prox 同配方
x_out  = (1 - M²) ⊙ x_s + M² ⊙ prox                     # 掩码门控合成
```

- 用的是**同一个 ε**（`make_eps(image_id, 0)`），与 ChordEdit 的 `_pred_x0` 逐项一致
  （两边都是 `timestep = round(t·max_timestep)`、`alpha = sqrt(abar)`，已核对）。
- 合成掩码用 `M²`：软掩码尾巴会把 prox 里的 `e_src` 漏回背景（PI 指出的第 ③ 点）。
- **副作用是一个大收益**：`(1-M²)⊙x_s` 相当于把掩码外**硬重置回源图**，所以它在背景 PSNR 上
  同时赢了"无 prox"和"全图 prox"（见 §0 表）。

## 3. Ours-5 vs ChordEdit：匹配背景 PSNR 的 A/B（**主判定**）

200 图；配对差 `s`（正 = 前者更好），2000 次图像级配对 bootstrap；匹配轴 = 背景 PSNR（官方口径
22.0 dB，实际落点 o5 **19.87** / chord **19.85**，ΔPSNR **+0.01 dB**，这次匹配得非常准）。

| 对比 | n | **s** | 95% CI | 胜率 | ΔPSNR |
|---|---|---|---|---|---|
| **Ours-5 − ChordEdit** | 200 | **−2.438** | **[−2.875, −1.594]** | **22%** | +0.01 |
| Ours-5 − 全图 prox（同 5 NFE） | 200 | −0.625 | [−0.875, −0.438] | 27% | +0.04 |
| Ours-5 − 无 prox（4 NFE） | 200 | −0.250 | [−0.344, −0.125] | 33% | +0.07 |
| Ours-5 − 无方向门控 | 200 | −0.187 | [−0.312, −0.063] | 39% | −0.07 |
| Ours-5 − 无低噪融合 | 200 | 0.000 | [−0.000, +0.062] | 55% | −0.01 |

**结论：Ours-5 没有追平 ChordEdit，差距反而比 P6 更大（−2.44 vs −0.91）。**

### 3.1 为什么变差了：三个修法各自都"有效"，但方向错了

把 §2 的前沿和官方指标摊开看（200 图均值）：

| run | 背景 PSNR（λ=1） | 全图 DINO↓ | **CLIP-Edited↑** | LPIPS↓ |
|---|---|---|---|---|
| o5 | **26.75** | 0.012 | **20.03** | 0.045 |
| o5_fullprox | 21.03 | 0.054 | **20.40** | 0.154 |
| o5_noprox | 22.30 | 0.036 | 20.31 | 0.095 |
| o5_nogate | 27.53 | 0.008 | 19.95 | 0.040 |
| **ChordEdit** | **22.02** | **0.031** | **22.59** | 0.125 |

**所有 Ours-5 变体的 CLIP-Edited 都卡在 19.9–20.4，而 ChordEdit 是 22.59 —— 差 2.2–2.6 个点。**
这不是效率问题、也不是背景保真问题，而是**语义强度**问题：我们的编辑根本"改得不够多"。

于是出现了这个反直觉的结果：

- **固定 λ 看**，掩码 prox 确实如你所料（λ=1：26.75 dB vs 无 prox 22.30 vs 全图 prox 21.03）；
- **但一旦把比较拉到"等背景 PSNR"**，掩码 prox 必须用 **λ=2.55**（全图 prox 只要 0.74）才能把背景
  降到 22 dB，于是它在掩码内部被推到过驱区，评委反而更不喜欢它（−0.63 vs 全图 prox）。
  换句话说：**掩码局部合成把"背景保真"变成了可以无限透支的额度，等 PSNR 匹配时这些额度全被
  花在破坏掩码内部上。**

### 3.2 真正的差距：ChordEdit 的场根本不是 R(0.9)

读它 `_u_estimate` 的最后三行（`third_party/ChordEdit/pipeline_chord.py`）：

```python
dv_s  = x_tar(t_s) - x_src(t_s)          # R(0.9)
dv_s0 = x_tar(t_s-δ) - x_src(t_s-δ)      # R(0.75)
return (δ * dv_s + t_s * dv_s0) / (t_s + δ)     # δ=0.15, t_s=0.9
```

→ `u = 0.143·R(0.9) + 0.857·R(0.75)`。**它的场 86% 来自 t=0.75**，而我们的 `u_h` 是 100% 的
`R(0.9)`。P3a 已经测过：`R(0.9)` 的随机占比 0.97、`R(0.7)` 是 0.96、`R(0.5)` 是 0.93 —— 高噪端
几乎全是噪声，**把 86% 的权重放在 0.75 上，等价于让"系统性部分"占比大幅提高**。我们的双尺度融合
把 `R(0.5)` 按范数对齐后加进来，但权重是拍的（等能量），不是弦权重，实测几乎没有效果
（o5 vs o5_nofuse = 0.00）。

**这就是为什么我们"改了但改不动"**：我们的场在语义上是弱的，而 ChordEdit 的场在语义上是强的。

### 3.3 一个不能忽略的反向证据：prox 可能把编辑"洗回去"

`o5 vs o5_noprox = −0.25`（无 prox 反而更好）。prox 在 `t_c=0.3` 用**目标** prompt 做一次 x0 预测，
低噪端条件很强，如果输入的 `y` 已经被推得很远，它很可能把结果拉回"干净且接近源图"的解 —— 于是
编辑被洗掉一部分。这一点需要单独验证（见 §5）。

## 4. 消融小结

| 组件 | 设计目的 | 实测 |
|---|---|---|
| 双尺度融合（按范数对齐） | 把已算好的低噪场用上 | **无效**（0.00 vs 无融合）→ 权重需要改成弦权重 |
| 方向门控 γ_dir | 抑制不可靠方向 | **轻微有害**（−0.19）；它改变了 u 与 A 的配比，归一后两者抢同一份预算 |
| 核心收紧 γ=2→3 | 减少掩码尾巴的 e_src 泄漏 | 背景 PSNR 略降（26.75→26.54 @λ=1），语义无改善 |
| 能量归一 | 防 k 项把步长撑爆 | **有效**（raw_norm 5–30× 波动 → 统一为 λ‖R_h‖）|
| Masked-Prox（+1 NFE） | 前景清理 + 背景保住 | **背景赢、语义输**：固定 λ 下 +4.4 dB；等 PSNR 下 −0.63 nat |

## 5. 结论与下一步（P8 建议）

### 5.1 三句话

1. **在同等 5 次前向、匹配背景 PSNR 下，Ours-5 输给 ChordEdit 2.4 nat（胜率 22%），比 P6 的
   −0.91 更差。**
2. **原因不是效率、也不是背景保真**：我们所有变体的 CLIP-Edited 都在 20 左右，ChordEdit 是 22.6。
   差距在**语义强度**。掩码局部合成把背景 PSNR 买到了 26–29 dB（你要的 26~30 达成了），但等 PSNR
   匹配时这份额度被花在过驱掩码内部上，评委因此更不喜欢。
3. **机制已经定位**：ChordEdit 的场是 `0.143·R(0.9) + 0.857·R(0.75)`，我们的是 100% `R(0.9)`。
   按 P3a 的方差分解，`R(0.9)` 有 97% 是噪声 —— 我们的方向从一开始就弱。

### 5.2 P8 应该先做的三件事（按性价比排序）

1. **换场**：把 `t_h` 从 0.9 换到 **0.75**（或直接采用弦权重 `(δR(t_s)+t_s R(t_s−δ))/(t_s+δ)`，
   用 0.75/0.9 或 0.5/0.75 两组）。这不是加 NFE：把 `t_h` 换个值而已，仍是 5 次前向。**这是唯一
   有明确机制证据的改法。** 我们的缓存只有 t ∈ {0.9, 0.7, 0.5}，0.75 需要重算 2 次/图（1400 次前向，
   约 3 分钟）。
2. **验证 prox 是否在"洗掉"编辑**：固定 λ（不匹配 PSNR），比较 `o5`/`o5_fullprox`/`o5_noprox` 的
   CLIP-Edited 与掩码内 LPIPS。如果 prox 把编辑洗回源图，那么"masked prox"这个方向就要重新设计
   （例如只在掩码边界用 prox，内部保留 y）。
3. **换匹配轴**：背景 PSNR 单独作匹配轴会奖励"毁掉掩码内部"的策略。P8 应该用
   **全图 DINO（或全图 LPIPS）匹配**，或者**双轴约束**（背景 PSNR ≥ 某值 且 全图 DINO ≤ 某值）。
   本轮数据已经显示三种轴会给出不同排序（背景 PSNR / 全图 DINO / CLIP-Edited）。

### 5.3 对论文定位的影响

本轮结果**不推翻** P6 定下的定位（可解释方差分解 + 两尺度/双算子分工 + 评测效度诊断），但要
诚实地写成：

> 我们给出了一个可解释的诊断框架（R 与 A 的角色分离、随机/系统能量的量化、评测指标效度的检验
> 方法）；在该框架下，5-前向的 Ours-5 在背景保真上优于 ChordEdit（同 λ 下 26.7 vs 22.0 dB），
> 但在匹配背景保真的语义轴上仍落后（CLIP-Edited 20.0 vs 22.6）。差距的根因已定位到编辑场的
> 时间尺度（我们用的是 t=0.9，其中 97% 是噪声），而不是效率或指标。

**不要**写"4 NFE 追平/超过 5 NFE 的 ChordEdit" —— 本轮的 200 图数据不支持。
