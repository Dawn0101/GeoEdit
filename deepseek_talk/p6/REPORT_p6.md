## 1. Stage 0：SDS 项的事前判定（`results/p6/report/p6_sds_diagnose.*`）

### 1.1 先纠正 P5 报告里的一处错误

P5 报告 §3 写过"SDS 项不需要额外前向，`x̂_tar(0.9) − x_s ≡ R₀(0.9)`"。**这是近似，不是恒等式。**

```
A(0.9) = μ_tar − x_s = R₀(0.9) + e_src,   e_src = μ_src(0.9) − x_s
R₀(0.9) = μ_tar − μ_src
```

`e_src = 0` 只在"UNet 的 ε 预测恰好等于注入的 ε"时成立（one-step 编辑的近似假设）。P3a 的 prep
只存了 `R` 和 `x_s`，把 `μ_src` 丢掉了，所以这个量从来没被测过。`scripts/60` 用 700 图 × 5 次
前向（4 seed @ t=0.9 + 1 @ t=0.5，2.1 分钟）把 `μ_src` 补回来，`scripts/61` 离线拆解：

| 量（700 图中位数） | 值 |
|---|---|
| ‖e_src‖/‖x_s‖ | 1.01 |
| **‖e_src‖/‖R‖** | **1.77** |
| cos(A, R) | **0.28** |
| cos(e_src, R) | −0.28 |
| 掩码内 frac_random：R | **0.9644** |
| 掩码内 frac_random：A | **0.5422** |
| 掩码外 frac_random：R / A | 0.9719 / 0.5553 |
| S_in(A)/S_in(R) | **32.7×** |
| 掩码内 SNR（S/V）：R → A | 0.037 → **0.844** |

**读法**：`R` 的掩码内能量 96% 是随机的（与 P3a 的 0.95–0.97 一致，说明分解本身没问题），而
`A` 只有 54% 是随机的 —— **A 的"可重复部分"比 R 高 20 倍以上**。也就是说 k>0 塞进掩码的
不是一个更大的 `R`，而是一个**跨 seed 稳定的方向**。这正是"橘猫改不动"所需要的性质，也是
你的判断被数据支持的地方。

### 1.2 但 A 不是更好的定位器（必须一起报）

把 4 个 seed 平均得到"系统部分"，它的能量图对 GT 掩码的 AUROC：

| 图 | AUROC（700 图中位数） |
|---|---|
| ‖mean_i R_i‖（系统部分能量） | 0.719 |
| ‖mean_i A_i‖ | **0.650** |
| ‖A_0‖（单次） | 0.639 |

⇒ **A 更可重复，但它的可重复部分并不更贴合编辑区**（更可能是模型自身的、与画面内容相关的
系统性偏差）。所以：

1. 不能用 A 当掩码（我们仍用 L5，P5 的 0.8565）；
2. k·A 必须在掩码内使用，否则会把这种"全局系统性偏差"带到背景上 —— 这正是 §3 的现象。

### 1.3 预注册判据的一次修正（`DEVIATIONS` P6-D2）

`configs/p6.yaml` 初版把门槛写成 `‖e_src‖/‖R‖ ≤ 1 才继续`，**方向写反了**：该阈值的本意是
"e_src 太**小**说明 A≈R、k 只是重标定"，而"大"恰恰说明 A 是另一个方向（对方法有利）。实测
1.77 落在这个反向阈值之外。修正为 `degenerate_if_e_src_over_R_below: 0.2`，并把实质判据明确为
**可重复性**（`frac_random(A) < frac_random(R)`，未改）。按实质判据：**通过，继续 k-sweep。**
两条数字都已写在 `p6_sds_diagnose.json` 里，任何读者都能复核这个修正。

## 2. 同源 A/B 闸门（`results/p6/ab/`）

### 2.1 强制二选一失败（`validity_lam010.csv`，100 图，λ=1）

问法：*"Two edited versions of the same photo are shown: image A is shown first, image B second.
… which version better follows the instruction? Answer with one word, A or B."*
取 `logP(A) − logP(B)`，两序各打一次求平均（A 标签按 `sha256(image_id)` 奇偶随机分配）。

| 检查 | 结果 | 判定 |
|---|---|---|
| C1 (V0,V0) 同图 | s = +0.063 [−0.062, +0.125] | ✅ |
| C2 换序一致性 | ρ(s_first, −s_second) = **−0.38** | ❌ |
| C3 (V2, 噪声) | +0.375 [−0.094, +0.687] | ❌ |
| C4 (噪声, V2) | −0.125 [−0.500, +0.281] | ❌ |
| C5 (V0, E1c) | +0.063 [−0.219, +0.312] | ❌ |

**原因**：`ρ = −0.38` 说明它按**位置**而不是内容作答；去偏后所有效应都塌到 0 附近。这与 P5 的
教训同源 —— 让 VLM 在一次前向里吐一个字母（A/B）时，该位置的分布几乎是平的
（`logP(A)−logP(B)` 只有 ±0.3 nat，而 Yes/No 量表有 ±5 nat 的动态范围）。

### 2.2 改用"同一源图的配对差"后通过（`validity_diff_lam*.csv`）

构造：对同一张源图，分别问 P5 里那个已验证的指令遵循问题，取两者之差

```
s = ½{ [q(src, A) − q(src, B)] + [q_sw(A, src) − q_sw(B, src)] }
```

两个候选共享同一个"画面变过了"地板，**地板在差里抵消**；每个差内部位置固定，也没有 A/B 位置
自由度；两序（源图在前 / 编辑图在前，措辞随之改写）仍各算一次并平均。

| 检查 | λ=1.0（n=100） | λ=0.5（n=100） |
|---|---|---|
| C1 同图 | **+0.000 [0, 0]** ✅（构造上应为 0，用于查接线） | +0.000 ✅ |
| C2 两序一致性 | ρ = +0.61 / +0.61 / +0.68 ✅ | +0.52 / +0.55 ✅ |
| C3 (V2, 噪声) | **+0.937 [+0.562, +1.251]** ✅ | +0.313 [+0.000, +0.564] 边缘 |
| C4 (噪声, V2) | **−0.937** ✅ | −0.313 边缘 |
| C5 (V0, E1c) 同幅度反向 | **+0.469 [+0.313, +0.688]** ✅ | +0.156 [−0.000, +0.344] ❌ |

**结论：闸门在 λ=1.0 上可用（五项全过），λ=0.5 上判别力不足**（效应 0.16 vs 0.47，CI 触 0）。
主判定因此用 **λ=1.0**。这也顺带回答了 P5 留下的问题：P5 的绝对量表失败是"绝对分含地板"，
不是"评委读不懂指令"；把两个候选做成配对差，同一个评委就能分辨方向了。

**代价与限制**（写进方法节必须带）：配对差每个候选要 2 次前向（正向 + 换序），一对候选 = 4 次，
是绝对量表的 4 倍；它只给出**相对**偏好，不能单独当"编辑成功"的绝对判据。

## 3. Ours-4 的定义与 50 组视觉对比（`results/p6/vis_k/`）

### 3.1 定义（4 NFE，与你的规格一致）

```
2 NFE  t_l = 0.5, seed 0 :  R0(0.5) → M = Gaussian(‖R0(0.5)‖, σ=2) 归一化到 max=1   (L5, AUROC 0.8565)
2 NFE  t_h = 0.9, seed 0 :  R0(0.9) = μ_tar − μ_src,  A0(0.9) = μ_tar − x_s        (SDS 项，0 额外前向)
更新                        x = x_s + λ·M ⊙ (R0(0.9) + k·M^(γ−1) ⊙ A0(0.9))
```

k=0 即"平滑掩码版 V12"（同族对照）；γ=1 掩码内均匀加推，γ=2 把加推集中到核心。

### 3.2 50 组（λ=1，均值）

| 变体 | 背景 PSNR↑ | LPIPS↓ | DINO↓ | CLIP-Edited↑ |
|---|---|---|---|---|
| k=0 | **28.17** | 0.042 | 0.003 | 19.88 |
| k=1 | 23.11 | 0.098 | 0.013 | 20.51 |
| k=2 | 19.18 | 0.176 | 0.028 | 21.03 |
| k=2, γ=2 | 23.35 | 0.085 | 0.011 | 20.52 |

固定 λ 看，k 越大改得越多、背景越坏 —— 所以**必须看匹配 PSNR**（§4）。γ=2 在同样的
CLIP-Edited 下把 PSNR 从 19.18 拉回 23.35，说明"集中到核心"确实降低了背景代价。

### 3.3 肉眼结论（逐张看过）

- `000000000005`"把猫从橘色改成黑色"：k=0 仍是橘猫（PSNR 33.2）；**k=1 猫头明显变黑**
  （23.6）；k=2 过推成黑块（19.3）；k=2,γ=2 介于两者（23.2）。
- `000000000027`"睁眼改闭眼"：k=0 几乎没变（24.2）；**k=1 头低下、眼睛闭合**（19.2）；
  k=2 头形崩坏（15.1）。
- 共同现象：k>0 让**语义真的发生**，但 k=2 会在掩码内留下黑块/形变；γ=2 明显缓解。

⇒ "橘猫变不成黑猫"的问题**确实是 k=0 推不动**造成的，k>0 修好了它；代价是掩码内的伪影。

## 4. 匹配背景 PSNR 的 A/B 主表（**主判定**）

设置：同一 200 图评测集。`s` = 配对差（正 = 第一个变体更好），2000 次图像级配对 bootstrap；
`|ΔPSNR|<1 dB` 子集是逐图匹配更严的口径。

**实际达到的背景 PSNR**（必须连同结果一起报，见 §9 P6-D4 / P6-D7）：目标是 24 dB 的两对实际落在
**21.5 / 21.7 dB**，目标是 22 dB 的那一对实际是 **19.4 / 19.9 dB**。原因是 λ 由**均值 PSNR 曲线**上
标量线性插值反解，而 `PSNR(λ)` 强烈非线性，且反解时前沿只跑了前 43 图（类别构成与 200 图不同）。
逐图 ΔPSNR 的均值为 −0.08 ~ −0.45 dB，标准差 0.5–3.2 dB，所以下面同时给"全部"和"`|ΔPSNR|<1`"
两个口径；两者的结论方向一致（子集大小 54 / 42 / 86 / 150）。

**口径提醒**：本表的 PSNR 是**背景像素上的 MSE**（比官方 `psnr_unedit` 更严——官方把编辑区置零后
除以全图像素数，系统性高 2–3 dB）。所以这里的 21.5 dB 与 §5 前沿曲线里的 23.9 dB 不是同一个数，
不要混着引用。匹配是否成立只看**逐图 ΔPSNR**，与这个偏移无关。

| 对比 | n | **s** | 95% CI | 胜率 | 平均 ΔPSNR |（两侧实际 PSNR） |
|---|---|---|---|---|---|---|
| **k=1 − k=0**（SDS 是否有用） | 200 | **+0.500** | **[+0.375, +0.750]** | **0.71** | −0.24 | 21.51 / 21.74 |
| k=1 − k=0，`\|ΔPSNR\|<1` | 86 | **+0.437** | **[+0.156, +0.813]** | 0.66 | −0.04 | — |
| k=2 − k=1 | 200 | +0.062 | [−0.000, +0.125] | 0.55 | −0.08 | 21.42 / 21.51 |
| k=2 − k=1，`\|ΔPSNR\|<1` | 150 | +0.063 | [−0.000, +0.125] | 0.57 | −0.09 | — |
| k=0 − V0（掩码有没有用） | 200 | +0.063 | [−0.063, +0.188] | 0.54 | −0.23 | 21.74 / 21.97 |
| k=0 − V0，`\|ΔPSNR\|<1` | 54 | +0.281 | [+0.062, +0.500] | 0.69 | +0.01 | — |
| **Ours-4(k=1) − ChordEdit** | 200 | **−0.906** | **[−1.312, −0.404]** | **0.35** | −0.45 | 19.40 / 19.86 |
| Ours-4(k=1) − ChordEdit，`\|ΔPSNR\|<1` | 42 | −0.844 | [−1.250, −0.124] | 0.33 | −0.10 | — |

### 4.1 预注册判定的结论

| 判定 | 结果 |
|---|---|
| **SDS 是否有效**（预注册主判定 `k=1 − k=0 > 0`，CI 不含 0） | **SUPPORTED**：+0.50 [+0.38,+0.75]，胜率 71%，且在严格匹配子集上仍成立（+0.44，66%） |
| k=2 vs k=1 | **无进一步收益**：+0.06，CI 触 0。**k=1 是甜点**，k=2 只增加破坏 |
| γ 核集中 | 见 §3.2：同 CLIP-Edited 下把 PSNR 从 19.18 拉回 23.35，是**降低背景代价**的有效旋钮 |
| 掩码本身（k=0 vs V0） | 全样本 +0.06（不显著），匹配子集 +0.28；**方向与 P5 一致但弱** |
| **vs ChordEdit** | **我们输**：−0.91 [−1.31,−0.40]，胜率 22%（与它同底座、同评测器、同 200 图） |

### 4.2 读法（必须连着说）

1. **你的方案被数据支持**：在同一个背景保真度上，打开掩码内 SDS 让"照指令编辑"的胜率从 50%
   升到 **71%**，效应 +0.5 nat，且不是靠牺牲背景换来的（ΔPSNR −0.24 dB，匹配子集 −0.04 dB）。
   §1 的机制解释也对得上：A 的掩码内可重复性是 R 的 20 倍以上。
2. **但 k 到此为止**：k=2 与 k=1 打平，只是更破坏（§3.2 PSNR 19.18 vs 23.11）。建议方法定 **k=1**。
3. **我们仍然打不过 ChordEdit**。这是本轮最重要的负面结果，而且它是在**最有利于我们的条件**下
   得到的（同底座、同 200 图、同评测器、同判官、匹配背景 PSNR）。注意这一对的实际 PSNR 是
   19.4 vs 20.1 dB（我们的 λ 反解偏大，见 §9 D4），但严格匹配子集（n=42）仍然是 −0.84。
4. **"4 NFE vs 5 前向"不足以构成卖点**（§5.1 双轨记账）。方法要立住，需要一个 ChordEdit 没有的
   东西 —— 目前唯一候选是 §1 的"两尺度分工"（t_l 只用 2 NFE 就拿到 0.8565 的掩码），但那属于
   **效率**而不是质量。

### 4.3 一个方法学提醒

`s` 是**相对**偏好，不是"编辑成功"的绝对判据。要与 PIE-Bench 的论文表格对齐，仍需同时报
§5.2 的四项官方指标（PSNR / LPIPS / DINO / CLIP-Edited）。ChordEdit 在同一 200 图上的
官方指标是 PSNR**22.02** / LPIPS 0.125 / DINO 0.016 / CLIP-E **22.59**。

## 6. 与 PreciseEdit 的关系（必须在论文里点名）

我们的更新式与 PreciseEdit 的 SCT 在数学上同族：

```
PreciseEdit eq.5-6 :  u = R_naive + k[μ_tar − x]      ← 就是我们的 R + k·A（M=1 时）
PreciseEdit eq.9   :  γ_dir = max(0, cos(u_h, u_l))    ← 用低噪方向抑制不可靠方向
```

差异只在：它用 cross/self-attention 图拉普拉斯做 PreciseMask，我们用 2 NFE 的能量掩码 L5；
它有方向一致性门控，我们本轮**没有**做（但它是 0 额外 NFE 的，因为我们本来就有 t_l 的场）。
**这条必须写进论文的 related work 与 diff 对比**，否则是新颖性风险。

## 7. 结论与下一步

1. **方法上定 k=1、γ 可作背景代价旋钮**；k 再大没有收益。Ours-4 = 4 NFE，定义见 §3.1。
2. **闸门用"同一源图的 Yes/No 配对差"，λ 固定在 1.0**（§2.2，五项效度全过）。强制二选一形式
   作废（§2.1）。这条可以写进方法节，也可以给后续项目复用。
3. **与 ChordEdit 的差距是下一步的第一优先级**：目前它在语义上领先 0.9 nat。可试的方向
   （按代价排序）：
   - 0 前向：把 PreciseEdit 的**方向一致性门控** `γ_dir = max(0, cos(u_0.9, u_0.5))` 乘上
     （我们本来就有两个尺度的场），这是唯一"既有文献证据、又 0 前向"的改进；
   - 2 前向：用 t_l 的 A（`μ_tar(0.5) − x_s`）做掩码内的低噪修正（BudEdit 的 gated refine 思路）；
   - 需要新前向：进入 8–10 NFE 区间与 ChordEdit 的 5 前向对齐（但那时"更省"的卖点就没了）。
4. **BudEdit 代码一旦发布立刻接入**（training-free，零权重），它是最接近我们的方法。
5. **论文定位**：如果继续以"更省 NFE"为卖点，必须承认质量未超 ChordEdit；如果以"两尺度分工 +
   可解释的方差分解"为卖点，则 §1 的诊断（A 比 R 可重复 20 倍、但定位更差）是真正的贡献点。
