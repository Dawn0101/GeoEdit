# v2 想法一页纸：一步编辑"够不够"，以及迭代能不能把它推远

> 完整推导与预注册假设见 [`docs/handoff/v2_p1_p2.md`](handoff/v2_p1_p2.md)；数据与判定见
> [`deepseek_talk/p2/`](../../deepseek_talk/p2/) 与 [`report/REPORT_p1_p2.md`](../../report/REPORT_p1_p2.md)。
> 本文只记录**结论**，供 v3 引用。

## 出发点

ChordEdit / FlowEdit 式的一步编辑是

```
z = a·x_s + b·ε,      R = x̂_tar(z) − x̂_src(z),      x_out = x_s + λ·R        (λ = 1)
```

在高噪声（t = 0.9）下 `a ≈ 0.12`，源图只剩 ~1/69 的信号。两个自然的问题：

- **P1**：`R` 在编辑区外面是否有一个**反号的"光晕"**？（高斯/Tweedie 线性化
  `R(x_s+δ) = (I−W)Δμ + Wδ` 预测：`W` 是低通，所以 `R` 在边界外会反向。）
  如果存在，说明背景损伤是**几何错位**，可以用各向异性预条件修。
- **P2**：一步是不是**改得不够**？如果是，就迭代 `δ_n = R(x_s + δ_{n−1})`（Picard），
  用不动点收敛把编辑推到"真正想去的地方"。

## 结论（都是负的，逐条给证据）

| # | 事实 | 证据 |
|---|---|---|
| F1 | λ、迭代次数 K、噪声水平 t 三个旋钮在 CLIP–PSNR 平面上走**同一条曲线**；Picard ≈ "多花 NFE 的 λ 放大"（K=2≈λ1.5，K=3≈λ2） | P2 主表；匹配 CLIP 后 Picard K=2 比 λ 曲线低 1.0 dB |
| F2 | 一步**不是编辑不足**：t=0.9 时 CLIP 在 λ≈1–1.5 饱和（≈24.4），再推只掉 PSNR | P2 |
| F3 | 高斯线性化不成立：迭代收缩率 c≈1（无各向异性可利用），**反号光晕不存在**（ρ 为正，且比 null 低 0.055） | P1 H1/H1b/H1c、P2 H2c |
| F4 | 背景损伤 ≈ VAE 底噪 + 很小的系统部分 + **很大的随机部分**（占 S+V 的 92%/94%/90% @ t=0.9/0.7/0.5），且 `MSE(N) = floor + S + V/N` 能在 N=1,6 上拟合、外推 N=2,4 误差 ≤ 0.0002 | 对 `deepseek_talk/p2/` 数据的离线拟合（**不在本仓库**，见下注） |
| F5 | 编辑区里**随机的那部分带语义**：6 次平均背景 20.3→25.4 dB，但 CLIP 24.37→23.71；匹配 CLIP 后平均只多赚 0.3–0.8 dB | P2 `avg` |
| F6 | 低 t 的残差更局部（e_rel 0.69/0.52/0.34 @ t=0.9/0.7/0.5），同 CLIP 下低 t 的 PSNR 更高，但 CLIP 上限更低 | P1 H1b、P2 全局 Pareto |

## 由此得到的教训（v3 的动机）

**全局降方差对背景是对的、对前景是错的。** ChordEdit 的时间平滑、P2 的多噪声平均，
都是"整张图一起平均/Gating"，所以都卡在同一条曲线上。要往前走，必须把两件事拆开：
**用多次噪声的统计量决定"在哪改"，用单次噪声的样本决定"改成什么"** —— 这就是 v3。

## 这一版**不**主张的事

- 不主张光晕/动态 OT/次黎曼那套叙述（P1 已否定）；
- 不主张 Picard 迭代能修好一步编辑（P2 已否定）；
- 不主张 prox 是必要组件（P2 里 prox 是独立因子，主分析用 raw）。
