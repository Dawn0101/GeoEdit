## 1. 先修语义指标

### 1.1 EditReward 排查：输入格式本来就对，**加载器是错的**

**格式核对（对照官方源码，`TIGER-AI-Lab/EditReward`，本机 clone 在 `/tmp/EditReward_off`）。**
逐项比对 `EditReward/inference_vl_edit.py` 与 `geoedit/editreward.py`：

| 项目 | 官方 | 我们（P4 起） | 一致 |
|---|---|---|---|
| 输入 | 单条 user message 里 **源图 + 编辑图 + 指令**，源图在前 | 同 | ✅ |
| 指令后缀 | `"\nPlease provide the overall ratings of this image: <\|Reward\|>\n\nEND\n"` | 同 | ✅ |
| 两维评分 | `batch_dim1` = INSTRUCTION_EDIT_FOLLOWING，`batch_dim2` = INSTRUCTION_EDIT_QUALITY | head_0 / head_1 | ✅ |
| 池化 | head 作用在**每个** token 上，取 `<\|Reward\|>` 位置 | 同 | ✅ |
| 分辨率 | `min_pixels = max_pixels = 256·28·28 = 200704` | 同 | ✅ |
| 输出 | 每头 `(mean, log σ)`，取 mean | 同 | ✅ |

**所以"只传了一张图"这类用法错误不存在。** 但同一次核对暴露了另一个问题：把 checkpoint 的
`embed_tokens` 形状（`[151666, 3584]`，151665 基础词表 + `<|Reward|>`）逼进 `config.json` 里的
`152064` 时，P4 的代码写的是

```python
config.vocab_size = 151666          # ← 外层（多模态）config 的便利字段
```

而文本塔读的是 **`config.text_config.vocab_size`**，它一直是 152064。于是 `from_pretrained`
报了形状不匹配，而 `ignore_mismatched_sizes=True` 把它**静默吞掉、随机重新初始化**：

```
model.language_model.embed_tokens.weight | MISMATCH | ckpt: [151666,3584] vs model: [152064,3584]
lm_head.weight                           | MISMATCH | Reinit due to size mismatch
```

视觉塔的形状是对得上的，**正常加载**；于是那个模型"看得见图像、但每个文本 token 都走随机的
词嵌入"。这解释了 E1d 的一切异常：分数几乎不随输入变化（dim1 全在 0.10–0.21 之间抖动），
并且"不编辑的原图"得分最高（0.79）——它实际上只是在给"图像自然度"排序。

**修法**（`geoedit/editreward.py`）：

- `config.text_config.vocab_size = 151666` 一并设置；
- `ignore_mismatched_sizes=False`（再出这种问题就直接报错，不再静默随机初始化）；
- 加载后断言 `embed 行数 == tokenizer 长度 == 151666`；
- `padding_side="right"`（与官方一致）。

**用官方 demo 图验证修复**（`assets/examples`，官方 README 的示例指令
"Add a green bowl on the branch"，`results/p5/judge_probe.json`）：

| 对比对 | 修复后 dim1（follow） | 修复后 dim2（quality） | 修复前 dim1 |
|---|---|---|---|
| (src, src) 不编辑 | **+1.137** | −1.564 | +0.170 |
| (src, target_1) | **+1.440**（+0.30） | −1.098 | +0.167 |
| (src, target_2) | **+1.855**（+0.72） | +0.034 | +0.168 |
| (src, target_3) | **+1.463**（+0.33） | −0.791 | +0.175 |

修复后：embed 行数 151666、三个"照指令编辑过"的目标图**全部高于不编辑**，量级也拉开了
（修复前四个对子挤在 0.163–0.175 的 0.012 宽度里）。位置偏置是小量但存在：交换图像顺序
后 +1.593 / +2.073 / +1.766，比正序高 0.15–0.30。

**另一个用法错误（这条是真的）：** P4-E1d 传的指令是 `tar_prompt`（目标 caption，例如
"a rusty mountain bicycle on the road…"），而文档 §1.1 要求用 PIE-Bench 自带的
`editing_instruction`（"Make the frame of the bike rusty"）。本次已改为
`editing_instruction`（`geoedit/data.py` 新增 `instruction` / `blended_word` 字段）。

⇒ **`results/p4/e1d/` 的全部结论作废**：包括"同幅度下平均不损失语义"（V1−V0 = −0.000）、
"只有 GT mask 被偏好"（V2−V0 = +0.103）以及 §0 第 3 条。它们不是"方向反了"，而是**没测到东西**。

### 1.2 第二个评委：Qwen2.5-VL 双图 Yes/No

`geoedit/vlm_judge.py`（与 EditReward 共用同一个 7B backbone，省一半显存）：

- 指令遵循：`logP(Yes) − logP(No)`，Yes/No 各自对四种拼写（`Yes` / ` Yes` / `yes` / ` YES`）
  做 `logsumexp`，在第一个答案位置读取，不生成；
- 保持分：同一形式，问题换成"除〈编辑对象〉外其余是否与第一张一致"，编辑对象取
  `blended_word` 的第一个词；
- **顺序检验**：`order="swapped"` 时把编辑图放在第一张，**同时改写"第一张/第二张"的措辞**，
  这样语义不变、只有位置变，两序的一致率就是位置偏置。

官方 demo 图上的行为（说明这个评委不是摆设）：不编辑 −4.64、target_1 +4.50、target_2 +5.38；
把指令换成错的（"Remove the bowl…" / "Turn the branch into metal"）得到 −5.63 / −7.50。

### 1.3 效度检验（540 图，类别 0–7，λ=1，四个控制全在 `results/p5/validity/`）

`G(v) = score(v) − score(recon)`，2000 次配对 bootstrap：

| 评委 | G(V0) | G(V2) | G(E1a) 错 prompt | G(E1b) 同包络噪声 | G(E1c) 反向 | 四项 |
|---|---|---|---|---|---|---|
| **CLIP-D**（P4 在任） | +0.049 [+0.039,+0.055] | +0.033 | +0.041（**84%**） | +0.031（**63%**） | +0.020（**正**） | ❌ |
| **EditReward dim1** | **−0.547** [−0.595,−0.485] | −0.273 | −0.788 | −0.667 | −0.623 | ❌ |
| **Qwen follow** | **+1.625** [+1.374,+1.875] | **+1.750** | +1.375（**85%**） | +1.000（**62%**） | +0.875（**正**） | ❌ |

| 检查 | 通过条件 | CLIP-D | EditReward dim1 | Qwen follow |
|---|---|---|---|---|
| 原图不是最高 | G(V0)>0 且 G(V2)>0，CI 不含 0 | ✅ | **❌** | ✅ |

| E1b 纯噪声 | < 0.25·G(V0) | ❌ | ✅（空过） | ❌ |
| E1c 反向 | ≤ 0 | ❌ | ✅（空过） | ❌ |
| **全部通过** | | **❌** | **❌** | **❌** |

**结论：三个评委没有一个通过。** 按 §1.3 的预注册，**停在这里**：不跑 §3 的语义对比，改为导出
50 组人工核对图（§1.4）。

三条要写进报告的读法：

1. **CLIP-D 是幅度计，这次是 540 图的确认。** 错 prompt 拿到 V0 增益的 84%（门槛 25%），
   纯噪声 63%，反向编辑仍然为正（41%）。P4 在 200 图上得到 73% / 41% / 不为负，同一结论。
2. **EditReward 修好以后依然过不了第一关：它认为"不编辑"最好。** 而且这一关一失败，后三项
   就是**空过**（G(V0) 为负时，"错 prompt 比 V0 更差"必然成立，不构成证据）。它在编辑结果内部
   的排序是对的（V2 > V0 > E1c ≈ E1b ≈ E1a），所以它**有指令方向感，但有强烈的"宁可不改"
   先验**。这一点直接对应它作为 Bradley-Terry 奖励模型的校准点：训练目标是"偏好的那张 > 不偏好
   的那张"，两者都是**编辑结果**，从未见过"原图 vs 编辑结果"当作合法对子。
3. **Qwen 的第一关过了、三个控制全部失败。** 它在真实编辑（官方 demo）上指令敏感度极强
   （错指令 −5.6），但在**我们 λ=1 的图上**，错 prompt / 纯噪声 / 反向编辑都能拿到 V0 增益的
   54–85%。这正是 §1.3 设计的用意：区分"评委本身不敏感"和"评委对这些图不敏感"。

   位置偏置（324 个图像×变体的子集）：following 两序符号一致率 **0.917**、Spearman **+0.805**；
   保持分 **0.861** / **+0.934**。顺序被交换后 following 平均低 0.85、保持分平均高 0.59。

**一个必须同时报告的混淆（不是借口，是下一步的实验设计输入）：** 这些控制全部在 **λ=1**，而
λ=1 的背景 PSNR 只有 **19.3 dB** —— 掩码外的画面已经被明显破坏。此时"这张图像是否按指令编辑
了"这个问题本身就退化了：任何评委都更可能基于"图像是否还自然"作答，而不是"改动方向对不对"。
这也是为什么 EditReward 直接判"原图最好"。按纪律这不是改阈值的理由（阈值预注册、已记录），
但它说明**效度检验的 λ 应该和方法的可用工作点一致**，而不是固定在最激进的点。已作为 P5 的
正式建议写进 §5。

### 1.3b 追加诊断：评委**读得懂**指令，失败的原因是增益被"变过了"吃掉

`E1a` 的对比有一个歧义：错 prompt 的残差拿到 85% 的增益，是因为 (a) 改动本身与指令无关、评委
只看画面质量，还是 (b) 评委在我们的图上根本读不出指令？两者对应完全不同的下一步。

`scripts/58_p5_instruction_sensitivity.py` 把它拆开：**图像对固定不动**，只换指令文本（换成
P4 置换伙伴的指令），40 张图（`results/p5/diagnostics/`）：

| 变体 | 用本图指令 | 用别人的指令 | **Δ（指令特异性）** |
|---|---|---|---|
| V0 | −3.840 | −5.931 | **+2.091** |
| E1b（同包络噪声） | −4.715 | −6.136 | **+1.421** |
| recon（不编辑） | −5.812 | −5.767 | −0.045 |

（Qwen following，logP(Yes)−logP(No)。EditReward dim1 同向但小一个量级：V0 +0.089、E1b +0.040，
且 recon 在真指令下 −0.213 —— 它确实在扣"没照指令做"的分。）

**所以 (b) 被排除：指令文本一换，分数就掉 1.4–2.1 nat。** 真正的机制是增益被拆成了两段：

```
V0 相对 recon 的增益   = +1.97 nat
其中"画面被大改过"的地板 = +1.10 nat（E1b 用真指令也拿得到）
剩下"改动方向对"的部分   = +0.87 nat
```

也就是说 **E1b 拿到 V0 增益的 56%（实测 62%），是"变了"这一项的地板，不是评委的噪声**。文档
预注册的 25% 门槛要求"方向信号必须占主导"，而这个要求在 λ=1 的破坏性工作点上**不可能满足**：
任何大幅改动都能拿到约 1 nat，V0 的方向信号只有 0.9 nat。

⇒ 这不是"换个评委"能解决的问题，也不该通过改门槛解决。它说明**效度检验的构造需要与工作点
匹配**：要么在方法可用的 λ 上检验（见下面的 λ=0.5 事后敏感性），要么把问题改成**同图对比的
A/B**（"这两张里哪一张更符合指令"，同一个源图、同一改动幅度，地板项会被减掉）。

### 1.3c 两个口径上的补充说明（防止误读）

1. **用官方"融合分"也是一样的结论。** 官方 README 的 `reward[0]` 是两头在 dim 0 上的平均
   （`pooling_strategy="mean"`）。按上面的均值算：recon −0.769、V2 −1.225、V0 −1.534、
   E1c −1.591、E1b −1.637、E1a −1.740 —— 排序不变，**原图仍然最高**。所以"只用 head_0"不是
   EditReward 失败的原因。
2. **EditReward 的分数是 Bradley-Terry 奖励，原点任意。** 它的训练对子是"两个编辑结果谁更好"，
   从来没把"不编辑"当作合法对子。它给出"原图最高"是可以预期的行为，而不是 bug；这也解释了
   为什么它在编辑结果**内部**的排序完全正确（V2 > V0 > E1c > E1b > E1a）。



### 1.3d 事后敏感性：把四个控制换到 λ=0.5 重跑（**事后，不替代上面的判定**）

动机见 §1.3 的混淆：λ=1 的背景 PSNR 只有 19.3 dB。同一套控制、同一批评委、540 图，
`results/p5/validity_lam050/`：

| 评委 | G(V0) | G(V2) | G(E1a) | G(E1b) | G(E1c) |
|---|---|---|---|---|---|
| Qwen follow | +0.625 [+0.375,+0.752] | +0.501 | **+0.750（120%）** | +0.501（80%） | +0.125（20%） |
| EditReward dim1 | −0.402 | — | −0.573 | −0.462 | −0.397 |
| CLIP-D | +0.027 | — | +0.020（74%） | +0.015（56%） | +0.008（30%） |

**降 λ 没有救回来，反而更糟，而且方向很清楚：**

1. **E1c（反向编辑）从 λ=1 的 +0.875 掉到 +0.125** —— 这是唯一一项如预期改善的；
2. **但 E1a / E1b 的比例反而升高**（85%→120%、62%→80%），因为 floor 项几乎不随 λ 缩小
   （"画面变过"这件事在 λ=0.5 仍然成立），而 V0 的方向增益从 +1.63 掉到 +0.63；
3. **λ=0.5 上 E1a（错 prompt）的增益 +0.750 甚至高于 V0 的 +0.625** —— 也就是在这个幅度上，
   评委对"改动方向"已经没有分辨力，任何改动都加约 +0.5~0.75。

⇒ **这是我此前假设的反例，如实记录**：不是"检验点太激进"，而是**这个方法的输出空间里"方向"
与"破坏"是纠缠的** —— 方向信号只在改动很大时才出现，而改动很大时画面已被破坏。所以任何"绝对
打分 + 和不编辑比"的闸门都无法通过，**无论 λ 取多少**。这条把 §5.2 的第 1 条（改成同源 A/B）
从"建议"升级为"唯一可行的形式"。

### 1.4 前沿：与背景 PSNR 匹配的语义分（**已执行，但因 §1.3 未通过而标为事后描述性**）

§1.3 没有任何评委通过，所以文档 §1.4 的前提不成立；但这一节的代价是**零新前向**（全部复用 P1
缓存残差），而且它是"乘性方差定律的推论在语义上是否成立"的唯一直接检验，因此仍然跑了，
**明确标为事后描述性**：它不用来做方法选择、不参与 §3 的预注册判定。

数据：200 图评测集，5 个变体 × 完整 λ 网格（6 点），Qwen following 为主、EditReward dim1 为辅
（`results/p5/frontier/`，纵轴高的方向 = 更符合指令）。

**匹配背景 PSNR ≈ 24.7–25.1 dB 处的配对差（2000 次图像级配对 bootstrap，单位 nat）：**

|---|---|---|
| **V1 − V0** | **−0.072 [−0.314, +0.157]** | +0.076 [+0.040, +0.110] |
| **S3-9 − V0** | **+0.019 [−0.180, +0.197]** | −0.024 [−0.053, +0.003] |
| **S3-9 − V1** | +0.090 [−0.128, +0.329] | — |

| **V2 − V0** | **+1.593 [+1.196, +1.974]** | −0.081 [−0.141, −0.019] |

| V2 − V1 | +1.664 [+1.245, +2.126] | — |

**读法（按 Qwen）：**

1. **V0、V1、S3-9 落在同一条曲线上**（三个差值的 CI 全部含 0，最大 |Δ| = 0.09 nat）。也就是说
   **单 seed / 4 seed 平均 / 最小离掩码能量的那一个 seed，在同一背景保真度下语义没有区别** ——
   这正是乘性方差定律的推论，之前只在 PSNR/CLIP-D 轴上看到过，现在在语义轴上得到确认。
2. **V12 明显在曲线之上**（+0.56 nat，CI 不含 0），**V2（GT mask）更高**（+1.59）。方向性打磨
   （用 t=0.5 的能量掩码去乘 t=0.9 的残差）确实买到了语义收益，而且不是在拿保真度换。
3. **匹配窗口必须说明**：V0 的 PSNR 上限约 25 dB（λ=0.5），V12/V2 的下限约 24 dB（λ=3），
   所以这个比较实际是"V0 最弱的幅度 vs V12/V2 最强的幅度"。这是匹配轴本身的性质，不是挑选；
   但写进论文时必须写明窗口。
4. **EditReward 与 Qwen 在 V12/V2 上符号相反**，而且它的效应量只有 Qwen 的 1/10（0.04–0.08 vs
   0.56–1.59），并且把 GT mask 判为最差。鉴于它连第一关（原图不是最高）都没过，这里以 Qwen 为准，
   EditReward 只作记录。

**顺带得到的一个硬数字（对方法定位很关键）：** 在 λ 网格上，**没有任何变体、在任何 λ 下把
Qwen 的分数推到 0 以上**（即"偏向 Yes"）—— 最好的 V2（oracle GT mask）也只到 **−2.82**
（λ=3，背景 PSNR 24.3 dB），而不编辑是 −5.62。也就是说：**即便给出真值掩码，这个 one-step 残差
编辑也没能让 VLM 评委相信指令被执行了**。配合 §1.3 的 50 张人工核对图（`results/p5/pairs/`：
V0 在 λ=1 把整幅画面毁掉；V12/V2 则干净但常常"什么都没改"，例如
`000000000005`"把猫从橘色改成黑色"仍然是一只橘猫），这就是 §1 真正的发现：
**方法目前没有工作点能同时满足"改到了"和"没改坏"**，指标只是把这件事测了出来。

## 2. 4 NFE 定位器（离线，无新前向；540 图，连续值 AUROC 对 `mask64`）

`scripts/53_p5_localizer.py`，产出 `results/p5/localizer/`。

| 记号 | 构造 | NFE | AUROC 均值 | **AUROC 中位数** |
|---|---|---|---|---|
| L0 | ‖R₀(0.5)‖，单 seed 不平滑 | 2 | 0.736 | 0.790 |
| L1 | pool3(L0) | 2 | 0.756 | 0.831 |
| L2 | pool5(L0) | 2 | 0.762 | 0.849 |
| L3 | Gaussian σ=1 | 2 | 0.759 | 0.840 |
| L4 | Gaussian σ=1.5 | 2 | 0.763 | 0.851 |
| **L5** | **Gaussian σ=2** | **2** | **0.766** | **0.857** |
| L6 | √(pool3 L0(0.5) · pool3 L0(0.9)) | 4 | 0.766 | 0.849 |
| L7 | 4 seed 平均能量（V12 用的 mask） | 8 | 0.773 | 0.858 |

**口径**：文档给的参照值是 **0.79（L0）和 0.858（L7）**，这两个数在本机复现出来是**中位数**
（对应均值 0.736 / 0.773；P3a 的 `mask_quality.csv` 里 t=0.5 diffedit 一行正是
mean 0.7730 / median 0.8581）。所以判定用中位数 —— 均值口径下"≥0.85"这一关**没有任何一项能
过**（最高 L5 = 0.766），中位数口径下 **L5 = 0.857 过线**。

**判定（按文档 §2）**：L1–L6 中最好的 L5 中位数 0.857 ≥ 0.85 → **过线**；但均值口径不过线。
两种口径结论相反，所以 §3（以及 §6 的事后前沿）**两条腿都跑**：4 NFE（L5）与 10 NFE（L7）。
这不违反预注册 —— 文档的 FAIL 分支本来就要求同时跑两个版本，而两条腿都不需要新前向。

**"相邻像素的随机部分近似独立"这个假设不成立：**

随机部分 `D_i = R_i − mean(R)`（4 seed，t=0.5）逐像素能量 `‖D_i‖` 去均值后的空间自相关：

| 滞后 | 编辑区内 | 编辑区外 |
|---|---|---|
| 1 px | **+0.572** | **+0.675** |
| 2 px | +0.385 | +0.501 |
| 3 px | +0.276 | +0.393 |
| 5 px | +0.154 | +0.270 |

（中位数；均值几乎相同。区外更高，因为背景平滑、残差跟着画面内容走。）

两个后果要分开讲：

1. **假设是假的**：随机部分在 1 px 上的自相关就有 0.55–0.68，远不是白噪声。
2. **但"平滑替代平均"在实践中仍然成立**：相关长度只有 1–2 个 latent cell，而 GT 掩码的尺度
   是 10–30 cell，所以 σ=2 的高斯核几乎不伤信号、却能砍掉大部分噪声方差 —— 这正是
   L5(0.857) ≈ L7(0.858) 的原因。文档里"自相关越高、平滑越不能替代平均"的推论在**固定滤波
   尺度**下方向是对的，但实际相关长度远短于信号尺度，所以结论要按尺度比来说，不能按自相关
   绝对值来说。

⇒ **给方法的结论：4 NFE 定位器可以用单个 seed + σ=2 平滑实现，AUROC 与 8 NFE 的四 seed
平均持平（0.857 vs 0.858），省掉 6 次前向。**

## 5. 结论与下一步建议

### 5.1 三个必须让 PI 知道的事实

1. **P4-E1d 作废，原因是一个真 bug**（词嵌入随机初始化）。它的所有结论（"平均不损失语义"、
   "只有 GT mask 被偏好"、"人类偏好差 < 0.005"）都**不能引用**。这是本期最重要的一条。
2. **§1 的三个评委一个都没过，按预注册停工。** 不是"再调一调"的问题：CLIP-D 是幅度计（第三次
   确认）；EditReward（修好后）有强烈的"宁可不改"先验，第一关就失败；Qwen 过了第一关，但
   "任何大幅改动都能拿 ~1 nat"这个地板项吃掉了 56% 的增益。
3. **§2 有一个正面结果可以写进方法**：4 NFE 定位器 = 单 seed ‖R₀(0.5)‖ + σ=2 高斯平滑，
   AUROC 中位数 0.857，与 8 NFE 的四 seed 平均（0.858）持平，**省 6 次前向**。

### 5.2 语义闸门应该怎么重做（P6 的 §1）

现在这个闸门的形式是"给单张编辑结果打绝对分"，再和"不编辑"比。它会系统性地失败，原因在 §1.3b
算清楚了：绝对分里含一个"画面变了"的地板项，而地板项与指令方向无关。三个具体修法，按建议顺序：

1. **改成同源 A/B**：同一个源图、同一改动幅度的两张结果（例如 V0 vs E1b，或 V0 vs E1c），问
   "哪一张更符合这条指令？"，取 `logP(A) − logP(B)`。地板项在同一个对子里被减掉，剩下的就是
   方向信号；正确率（A 该赢的比例）直接就是一个可解释的效度指标，不需要"增益百分比"这种
   跨尺度的阈值。
2. **把效度检验放在方法的工作点上**：λ=1 的背景 PSNR 只有 19.3 dB，这个点上"是否按指令编辑"
   本身已经退化成"图像是否还自然"。至少应同时在 λ=0.5（或"同背景 PSNR"的匹配点）上检验。
3. **保留"原图不是最高分"这一关**：它是唯一一条不依赖尺度、只依赖序的检查，而且确实能筛掉
   EditReward 这种"宁可不改"的先验。

  预注册（Ours-4 相对 ChordEdit ΔPSNR ≥ +1 dB）因此**一次都没被检验过**。建议下一个周期优先补
  BudEdit（它是最接近我们的方法：残差能量定位 + 两个 t），并把权重下载与依赖适配当作独立任务。
