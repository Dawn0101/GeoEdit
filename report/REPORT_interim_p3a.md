## 0. 一句话

**v3 的核心主张在 PIE 上没有成立，而且原因可以定位到具体一项：预先注册的 SNR 权重
`T = N·M̄/(4·S̄)` 在真实残差上不是定位器（AUROC 0.49），因为编辑区里"平均能量"和"方差"
几乎同比放大（t=0.5 时 8.19 vs 8.27），比值把空间信息抵消掉了。** 同一个残差，
DiffEdit 式的 N 次平均能量能到 AUROC 0.86。

## 1. 评测口径（§1 的修正）

三件事查清了，结论是**数值没错，列名与一处口径错了**：

| 我们的列 | 官方 `evaluate.py` 的列 | 关系 |
|---|---|---|
| `clip_target_whole` | `clip_similarity_target_image` | 同一量 |
| `clip_target_edit` | `clip_similarity_target_image_edit_part` | 同一量（P2 里被 `lean=True` 跳过，本次补上）|
| `clip_source_whole` | —— | **不同量**：官方 `clip_similarity_source_image` 是 `CLIP(源图, 源 prompt)`，与输出无关（对每张图是常数）；我们是 `CLIP(输出, 源 prompt)` |

- P2 的 `clip_whole` = 我们现在的 `clip_source_whole`（对源 prompt 算），P2 的 `clip_edited` = 现在的 `clip_target_whole`。**P2 的数值没错，只是命名有歧义**，报告里已按上表改写。
- **T-X3 通过**：7 个同定义的量（4 个背景指标 + 2 个 target CLIP + 结构距离）与官方 `evaluate.calculate_metric` 在 20 张图上逐项 max|Δ| < 1e-4；并且用两张完全不同的输出验证了"官方 source-CLIP 是常数"（差 < 1e-6）。测试把它固定下来，见 `tests/test_p3.py::test_t_x3_metrics_match_the_official_evaluator`。
- 因此 **`clip_target_edit` 是主语义指标**（不是 whole）：whole 版本对 mask 方法有免费加成（见 §5 的事后对照）。

## 2. 预注册假设的判定（t=0.9，n=540 图，主分析排除类别 8/9）

| 假设 | 判定 | 数字 |
|---|---|---|
| **H3a** 单次样本比平均更有语义（GT mask 内） | **INCONCLUSIVE** | max_λ CLIP(V2−V3) = **+0.056**，95% CI **[−0.117, +0.224]** |
| **H3b（主）** SNR 权重把前沿往外推 | **NOT_TESTABLE（设计层面）** | 预注册锚点 CLIP = 19.881 / 19.957；V4 的 CLIP 值域是 **[19.627, 19.892]**（最高点出现在 λ=3 的端点），第二个锚点在值域之外 ⇒ 不外推就无法判定 |
| **H3c** 比 DiffEdit 式 / 单次能量 mask 好 | **NOT_TESTABLE（设计层面）** | V7/V8 的 CLIP 全程低于 V0 的最低点（λ=0.5 时 19.70），与 V0 **没有公共 CLIP 区间** |
| **H3d** 随机能量占比：mask 外 > mask 内 | **SUPPORTED** | 配对 Wilcoxon p = **2.5e-8**，但中位差只有 **+0.0076**（n=484）|

> **H3d 的"支持"要打折看**：编辑区内外的随机占比分别是 0.968 / 0.973（t=0.9）、0.930 / 0.948（t=0.5）。
> 也就是说**残差几乎全是随机的**，任何 0.01 量级的差都会因为 n=484 而显著。这一条在统计上成立、
> 在物理上没有信息量。它是"用方差定位"这条路线的**否证**，不是支持。

## 3. mask 质量：预先注册的构造不是定位器

AUROC 按 §2.1 用**连续值**算（第一次跑时我们对 V7/V8 用了二值 mask，已修正，见 D12）。
t=0.9 中位値：

| mask | t=0.5 | t=0.7 | t=0.9 | IoU (t=0.9) | 面积占比 |
|---|---|---|---|---|---|
| **w4（SNR 权重，主方法）** | **0.492** | 0.481 | 0.486 | 0.048 | 11.4% |
| w2（N=2） | 0.495 | 0.479 | 0.483 | 0.055 | 12.4% |
| **DiffEdit 式（N=4 平均 ‖R‖）** | **0.858** | 0.855 | 0.781 | 0.072 | 4.7% |
| 单次 ‖R₀‖ | 0.790 | 0.783 | 0.708 | 0.012 | 1.1% |
| 跨 t 相乘 w(0.9)·w(0.5) | — | — | 0.491 | 0.000 | 0.3% |
| GT（参照） | 1.000 | 1.000 | 1.000 | 1.000 | 34.1% |

两条结论：

1. **N=4 平均能量 ≥ 单次能量**（0.858 vs 0.790 @ t=0.5；0.781 vs 0.708 @ t=0.9），与预期一致；
2. **SNR 归一化把定位能力完全抹掉了**（0.49），而原始能量是 0.78–0.86。

**根因**（20 张图，latent 空间，GT 内外均值比）：

```
t=0.5：平均能量 in/out = 8.19     方差 in/out = 8.27
t=0.9：平均能量 in/out = 2.56     方差 in/out = 2.30
```

`T = N·M̄/(4·S̄)` 是两个同比缩放的量相除 ⇒ T 在空间上近似常数（中位 1.38，`w_in` 0.295 vs `w_out` 0.268）。
高斯模型的假设是"背景 m≈0、前景 m 大"，真实情况是**背景的方差也小**，比值把信号抵消。
**这是构造层面的缺陷，不是实现 bug**（对齐已独立验证，见 §4）。

## 4. 对齐核查（回应"mask 和 latent 错位"的怀疑）

| 检查 | 结果 |
|---|---|
| `mask64 == avgpool8(mask512) > 0.5` | 50/50 张**逐元素相等**，无转置/翻转 |
| 空 mask64 的图 | 0 张（GT 面积中位 0.341，5% 分位 0.026）|
| 残差是否落在 GT 上 | 原始能量 AUROC = **0.79 (t=0.5) / 0.71 (t=0.9)**，内外能量比 7.3× / 2.4× |
| 同 λ 下 GT mask 是否有效 | **V2 = M_gt⊙R₀ 在 λ=1 时 PSNR 30.26 vs V0 20.25（+10.0 dB），CLIP-Edited 只差 −0.17** |

⇒ mask 与 latent 对齐无误；GT oracle 工作正常。**不是 bug。**

## 5. 前沿在哪里（t=0.9, λ=1，n=540，raw）

| 变体 | 背景 PSNR | CLIP-Edited | CLIP-whole |
|---|---|---|---|
| recon（上界） | 32.5 | 19.57 | 23.21 |
| **V0 = R₀** | 20.25 | **19.957** | **24.17** |
| V1 = m̂₄（全局平均） | 24.55 | 19.864 | 23.72 |
| **V2 = M_gt⊙R₀**（oracle 位置 + 单次） | 30.26 | 19.788 | 23.91 |
| V3 = M_gt⊙m̂₄ | 31.86 | 19.750 | 23.54 |
| **V4 = w₄⊙R₀**（主方法） | 28.84 | 19.701 | 23.43 |
| V5 = w₄⊙m̂₄ | 29.98 | 19.719 | 23.36 |
| V7 = DiffEdit 式 ⊙R₀ | 26.54 | 19.393 | 23.01 |
| V8 = 单次能量 ⊙R₀ | 27.42 | 19.391 | 22.90 |

**读法**：同 λ 下 mask 版本大幅胜出（+8～10 dB），但**CLIP 全部低于 V0**，因为 V0 可以
用更小的 λ 换到同样的背景 PSNR。事后在**匹配背景 PSNR** 方向上看（这个方向数值稳定）：

| 匹配 PSNR | V0 | V1 | V2 | V4 | V11 |
|---|---|---|---|---|---|
| 25 dB | 19.70 | **19.85** | 19.38 | 19.82 | 19.78 |
| 28 dB | —（OOR）| 19.70 | 19.69 | **19.72** | 19.72 |
| 31 dB | —（OOR）| —（OOR）| **19.80** | —（OOR）| 19.65 |

⇒ **掩码没有把前沿推出去，只是沿曲线滑动；SNR 权重（V4）≈ 全局平均（V1）。** 注意 V4 的 CLIP 上限（19.892）本身就低于 V0 在 λ=1 时的 19.957——**掩码把 CLIP 天花板压低了 0.065**，这是 H3b 在第二个锚点上不可测的直接原因。 唯一略胜的
是 oracle 位置（V2）在 31 dB 处 +0.15 CLIP，且置信区间与 V1 重叠。

**事后·公共 CLIP 区间锚点**：V0 在 CLIP 19.7–19.83 这一段几乎是垂直的（dPSNR/dCLIP ≈ 30 dB/分），
按 CLIP 插值 PSNR 的 bootstrap CI 宽达 10 dB（例如 V0 在 CLIP=19.70 处 24.5 dB，CI [14.5, 24.8]），
**这个方向不可用**；V7/V8 与 V0 连公共区间都没有（它们在整个 λ 网格上都被 V0 在 CLIP 上支配）。
这条负面结论本身是可信的：**逐像素 mask 在 CLIP–PSNR 平面上不产生新前沿**。
